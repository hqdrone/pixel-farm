# Пиксель-Ферма: English

Веб-приложение для двух детей (8 и 9 лет), которые учат английский. **У каждого ребёнка свой телефон.** Приложение открывается по постоянной ссылке на GitHub Pages.

Дети учат английский с нуля на телефоне. Игровая форма, озвучка, пиксельная графика. Прототип уже работает. Задача: развивать его дальше, а не переписывать.

Общайся со мной по-русски. Весь интерфейс приложения на русском, учебный контент на английском.

## Главные принципы (не нарушать)

1. **Минимальные затраты.** Без сервера, без платных API, без подписок. Хостинг: GitHub Pages, статический сайт. Озвучка через встроенный `speechSynthesis` браузера.
2. **Дети должны хотеть играть сами.** Короткие сессии по 5–10 минут, никаких наказаний за ошибки, видимый результат (ферма растёт), награды (звёзды, сундук дня, серия дней).
3. **Реальная польза.** Каждое слово проходит путь «услышал → узнал → произнёс → написал». Интервальное повторение обязательно.
4. **Пиксельная графика, но узнаваемая.** Спрайты 16×16 рисуются кодом, без картинок. Каждый новый спрайт проверяй глазами на листе превью (см. ниже). Если предмет нельзя узнать без подписи, перерисуй его.
5. **Сначала телефон.** Ширина 360–480px, крупные кнопки, всё нажимается пальцем.
6. **Без сборщиков и фреймворков**, пока это не понадобится по-настоящему. Чистый JS, один итоговый HTML-файл.

## Сохранность прогресса (критично)

Весь прогресс хранится локально в браузере телефона (`localStorage`). Обновление приложения **никогда** не должно стирать прогресс.

- **Один постоянный адрес.** Дети открывают только `https://<user>.github.io/pixel-farm/`. Любой другой адрес (localhost, копия на другом хостинге) — это пустое хранилище. Домен и имя репозитория не менять: смена адреса = потеря прогресса.
- **Ключ хранилища не переименовывать.** Ключ `pixelfarm-en-v1` остаётся навсегда. Если структура данных меняется, хранить в объекте поле `schemaVersion` и при загрузке прогонять миграции по шагам (v1→v2→v3…). Старые поля не удалять, пока миграция их не перенесла. Ни одного вызова `localStorage.clear()` или перезаписи пустым объектом при ошибке разбора: при битых данных сохранить их копию под ключом `pixelfarm-en-backup-<дата>` и только потом начинать заново.
- **Защита от очистки браузером.** При первом запуске вызвать `navigator.storage.persist()`. iOS Safari может стереть данные сайта, который не открывали 7 дней, если он не добавлен на главный экран. Поэтому приложение должно подсказывать: «Добавь меня на главный экран» (для iOS с картинкой-инструкцией «Поделиться → На экран Домой»). Установленное PWA этой очистке не подвержено.
- **Резервная копия.** На экране родителя кнопки «Сохранить прогресс» (показать код или скопировать его в буфер, JSON → base64) и «Восстановить из кода». Это страховка на случай смены телефона или очистки браузера. Сервер не нужен.
- **Service worker не должен держать старую версию.** Для `index.html` использовать стратегию «сначала сеть, потом кэш» (офлайн работает, обновления приходят сразу). `sw.js` регистрируется с `updateViaCache: 'none'` (на GitHub Pages свои заголовки задать нельзя). Кэш service worker хранит только файлы приложения и никогда не трогает `localStorage`.
- **Тест на сохранность.** В `tools/playtest.js` добавить проверку: пройти урок → пересобрать → перезагрузить страницу → прогресс на месте. Отдельный тест миграции: положить в `localStorage` данные v1 из фикстуры, загрузить новую версию и проверить, что слова, звёзды и серия сохранились.

## Профили

У каждого ребёнка свой телефон, поэтому при первом запуске один профиль: спросить имя и выбрать аватар. Возможность добавить второй профиль на том же телефоне оставить (например, если телефон разрядился), но не показывать двух «Игроков» по умолчанию.

## Деплой на GitHub Pages

`.github/workflows/pages.yml`: каждый push в `main` запускает `node build.js` и выкладывает `dist/` на GitHub Pages (Settings → Pages → Source: GitHub Actions). Адрес `https://<user>.github.io/pixel-farm/` постоянный, его и давать детям. Репозиторий не переименовывать: это меняет адрес. GitHub Pages не даёт задавать заголовки, поэтому `sw.js` регистрируется с `updateViaCache: 'none'`, а сам SW запрашивает файлы с `cache: 'no-cache'`.

## Структура

```
src/app.html        — всё приложение: стили, логика, экраны, контент (ITEMS, TOPICS)
src/sprites.js      — PALETTE, SPRITES (16x16), LETTERS5x7 (пиксельный шрифт для фермы)
src/sw.js, src/manifest.json — PWA: service worker («сначала сеть») и манифест
build.js            — node build.js → dist/ (index.html со спрайтами, sw.js, manifest.json, иконки PNG из спрайта)
dist/               — готовое приложение (в git не хранится, собирается в GitHub Actions)
tools/fixtures/v1.json — данные прототипа для теста миграции
tools/sprite-sheet.js — проверка размеров спрайтов + превью tools/sprite-sheet.html
tools/playtest.js   — автотест (playwright): все темы, сохранность при обновлении, офлайн, миграция, битые данные; скриншоты в tools/shots/
```

После любой правки: `npm test` (= `node build.js && node tools/sprite-sheet.js && node tools/playtest.js`). Перед тем как сказать «готово», посмотри скриншоты из `tools/shots/`.

## Как устроен код (src/app.html)

- **Контент.** Массив `TOPICS` (id, ru, en, icon) и массив `ITEMS`. Элемент: `{id, topic, en, ru, sprite, color?}`. У букв ещё `letter` и `ex`, то есть слово-пример с готовым спрайтом.
- **Спрайты.** Каждая строка ровно 16 символов. При `sym:true` строки по 8 символов и зеркалятся. Символ `.` значит прозрачность, `X` заменяется цветом, переданным при отрисовке (цветной шарик, цветок). Цвета задаются буквами из `PALETTE`.
- **Хранилище.** `localStorage`, ключ `pixelfarm-en-v1`, обёрнут в try/catch. В объекте `DB` лежат `profiles[]` и `settings` (ruVoice, unlockAll, rate). Профиль: `{name, avatar, stars, streak, lastDay, chestDay, words:{[id]:{box,due,seen,right,wrong}}, decor[]}`.
- **Интервальное повторение.** `INTERVALS` = 0, ½ дня, 1, 3, 7, 14 дней по ступеням `box` 0..5. Урок без ошибок поднимает ступень на 1, с ошибкой опускает на 1. Слово считается выученным прочно при box ≥ 3, на ферме у него появляется искорка.
- **Урок** (`startLesson`). До 4 новых слов темы, затем 3–5 слов на повторение со всех тем, у которых подошёл срок (сначала те, где больше ошибок). Порядок: карточки знакомства (`intro`), потом перемешанные задания. Неправильно решённое задание один раз добавляется в конец урока.
- **Типы заданий** (объект `TASKS`):
  - `intro`: знакомство со словом, ребёнок повторяет вслух;
  - `listen`: найти картинку на слух;
  - `see`: выбрать слово по картинке (у букв: «с какой буквы начинается»);
  - `spell`: собрать слово из букв;
  - `memory`: найти пары картинка–слово.
- **Ферма** (`Farm`). Canvas 192×160 с анимацией. Изученные слова занимают фиксированные места: животные ходят, еда лежит на грядке, цвета растут цветами, буквы стоят кубиками. Если нажать на объект, он произносит своё слово.
- **Темы** все открыты сразу, ребёнок выбирает сам.

## Известные ограничения прототипа

- Микрофон не использовался: прототип жил в песочнице, где он заблокирован. Сейчас ребёнок повторяет слово вслух и сам нажимает «Я сказал!».
- Прогресс хранится только в браузере одного телефона (так и задумано), но пока нет резервной копии и миграций.
- Голос зависит от телефона (на iPhone хороший, на части Android роботизированный).
- Шрифт Andika (Google Fonts): создан для обучения чтению, буквы не путаются, есть кириллица. Офлайн берётся из кэша service worker.
- Голос нельзя включить без нажатия: iOS разрешает речь только после касания. Первая фраза звучит при выборе профиля, это нужно сохранить.

## План развития (по порядку, каждый шаг отдельно и с проверкой)

1. ✅ **Деплой и сохранность.** GitHub Pages, PWA (`manifest.json`, иконка из спрайта, которую скрипт генерирует в PNG, и service worker со стратегией «сначала сеть»), `schemaVersion` и миграции, `navigator.storage.persist()`, подсказка «Добавь на главный экран», один профиль при первом запуске. Плюс тест сохранности прогресса.
2. **Резервная копия прогресса:** экспорт и импорт кодом на экране родителя.
3. **Проверка произношения.** `webkitSpeechRecognition` / `SpeechRecognition` с языком en-US. Ответ засчитывать нестрого (слово входит в варианты распознавания или очень похоже). Если API нет, оставить нынешнюю кнопку «Я сказал!». Ребёнка за плохое распознавание не наказывать, максимум мягкое «давай ещё раз».
4. **Вынести контент в `src/content.js`**, чтобы новые темы добавлялись без правки логики.
5. **Весь алфавит A–Z.** Для каждой буквы слово-пример со спрайтом и пиксельный глиф 5×7 в `LETTERS5x7`.
6. **Новые темы** (по 8 слов, сначала только конкретные предметы): числа 1–10, семья, тело, одежда, дом, школа, игрушки, погода.
7. **Действия и чувства** (run, jump, eat, sleep, happy, sad…): спрайты в 2–3 кадра анимации.
8. **Этап фраз:** «I like…», «I have…», «This is…», «What's your name?». Новое задание: собрать фразу из слов-карточек. Затем мини-диалоги с персонажами фермы.
9. **Экран родителя:** график по дням, слова на повторение, время в приложении.
10. **(Необязательно)** заранее записанная озвучка в mp3 для стабильного качества, но только если родитель согласится на разовые затраты.

## Правила работы

- Не ломать сохранённый прогресс детей: см. раздел «Сохранность прогресса». Любое изменение структуры данных = миграция + тест миграции.
- Новый спрайт: нарисовать, запустить `node tools/sprite-sheet.js`, открыть превью и честно оценить, узнает ли его ребёнок 8 лет.
- Новый тип задания: добавить его в `TASKS` и обработку в `tools/playtest.js`.
- Тексты для детей короткие, дружелюбные, на «ты». Ошибка звучит как «Почти! Попробуй ещё», а не «Неправильно».
